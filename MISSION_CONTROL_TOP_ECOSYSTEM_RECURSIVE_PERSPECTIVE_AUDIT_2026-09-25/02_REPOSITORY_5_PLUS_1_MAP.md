# 02 — Repository 5+1 Map

## Observed structure

| Position | Repository / surface | Bounded primary role | Authority retained locally |
|---:|---|---|---|
| 1 | NEXAH Core | semantics and framework | conceptual definitions and core framework |
| 2 | Science Lab | evidence and research records | experiments, derivations, negative results, evidence status |
| 3 | ORION | deterministic processing | processing contracts, reproducible transformations, certified behavior |
| 4 | NEXAHEDRON | human interaction | interaction mechanics and human-facing operation |
| 5 | NEXAH Experience | public presentation | public rendering, navigation, and experience surface |
| +1 | Mission Control | currentness, routing, and portfolio control | operational truth surface, pointers, states, and coordination records |

The certified ORION checkout is a reference/shadow of ORION, not a sixth peer role.

## Interpretation

The `+1` does not own, merge, or supersede the five repository authorities. Mission Control binds the comparison by maintaining a situated control view: what is current, where the authority remains, and which return is still open.

This matches the NEXAH binder constraint:

> A binder is a situated reference role, not a universal center, cause, owner, or proof of identity.

The repositories are therefore not interchangeable pictures of one object. They are autonomous, authority-bounded systems whose outputs can become inputs to another system through explicit handoffs.

## The present TOP perspective

The audit perspective itself should be recorded as observer metadata rather than counted as another repository:

```text
Q°_TOP(t) = observer position + date + source set + declared cut + claim ceiling
```

This avoids an infinite `+1` regress. TOP is the declared perspective from which the existing `5+1` is compared; it is not a seventh system and it receives no independent scientific authority.

## Existing strengths

- Responsibilities are separated rather than collapsed.
- Authority generally remains at the source repository.
- Mission Control points to sources instead of silently replacing them.
- Public presentation is separated from evidence and processing.
- Certified ORION state is distinguished from the working repository.
- Human STOP/ABSTAIN and bounded-claim language already exist.

## Recursive application gap

The ecosystem currently has a **node register** but not a common **edge ledger**.

The role of each repository is described, and broad flow arrows exist. What is not consistently recorded for each handoff is:

- the source artifact and source authority;
- the receiving frame, cut, or operation;
- what was retained;
- what was lost;
- what was introduced;
- what remains unresolved;
- the typed residual;
- the return route and closure condition.

Accordingly, the gap is classified as:

```text
RECURSIVE_APPLICATION_GAP
```

It is not classified as absence of architecture.
