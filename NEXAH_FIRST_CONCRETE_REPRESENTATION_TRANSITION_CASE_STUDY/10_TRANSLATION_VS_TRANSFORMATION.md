# Translation versus Transformation

## Operational distinction

The distinction is useful only when tied to a declared scientific object and criterion:

- **Translation:** a change of representation intended to retain a named object or quantity under an explicit equivalence/recovery criterion.
- **Transformation:** an operation assessed as changing at least one named scientifically relevant property or as constructing a different derived object.

These are roles, not intrinsic labels for an operator in all contexts.

## Application to this case

| Operation | Operational reading |
|---|---|
| Baseline packaging T02 | translation: elementwise identity of observations/labels/indices |
| Delay embedding T03 | translation with respect to current-observation recovery; transformation with respect to metric geometry used by the decoder |
| Global normalization T04/T05 | translation for pairwise distance ratios/order; transformation for absolute origin and scale |
| Clustering T06/T07 | transformation: continuous geometry becomes a many-to-one partition |
| Oracle alignment | translation of anonymous cluster names only if the permutation correspondence is accepted; it cannot restore misassigned samples |
| Transition counting | transformation/projection: ordered sequence becomes adjacency multiplicities |
| Certificate ladder | a family of projections with explicitly different retained distinctions |
| Threshold classification T12 | transformation: numerical aggregates become categorical interpretation |

The case rejects a global binary label. T03 is simultaneously a lossless translation for one object and a scientifically consequential transformation for another. Therefore the useful vocabulary is `operator + object + criterion + scope`, not symbolic oppositions.

Rotation, reflection, inversion, folding, and convex/concave language are absent because no such operator occurs in this selected chain.
