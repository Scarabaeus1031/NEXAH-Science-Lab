# V2 Self-Check

| Prior failure | V2 behavior |
|---|---|
| ambiguous boundary | explicit resolution and composite components; unresolved blocks strongest claim/implementation states |
| preservation without criterion | schema requires criterion type/text/result/evidence |
| loss without criterion | schema requires category/distinction/criterion/result/evidence |
| task claim without source | defined task requires source, owner, criterion, and consequence |
| symbolic evidence supports claim | nontechnical eligibility requires empty `supports_claim_ids` |
| execution confused with science | separate execution/reproducibility and claim-support dimensions |
| negative result overwritten | append-preserving lineage and prior-claim retention rule |
| fabricated precision | quantified/bounded uncertainty requires method and evidence; truth still requires review |
| missing provenance concealed | every link carries explicit state; aggregate sufficiency is judged/evidenced |

Legitimate incomplete records remain possible: artifacts can be absent, provenance can be unavailable, uncertainty can be not applicable/unknown, task relevance can be undefined, and boundaries can remain unresolved. These states prevent unsupported upgrades rather than invalidating the record.

The four sample YAML files were designed against the schema. Only YAML syntax and schema conformance are in scope; scientific conclusions remain bounded by cited evidence.
