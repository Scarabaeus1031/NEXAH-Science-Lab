# Research Flow Assessment

## Compared flow

```text
Observation
→ Pattern
→ Geometry
→ Research Question
→ Definitions
→ Literature
→ Formalization
→ Experiments
→ Results
→ Review
→ Lab Report
→ Archive
```

## Current fit

| Stage | Existing practice | Assessment |
|---|---|---|
| Observation | Field Notes, source records, experiment logs, visual Works | strong preservation; status often clear |
| Pattern | Library, whiteboards, Findings and research narratives | abundant; recurrence can be mistaken for evidence |
| Geometry | Foundation, Core Concepts, Observer Lab, application models | extensive; definitions vary by program |
| Research Question | present in many READMEs, logs and reviews | fragmented; no single stable question identity |
| Definitions | OLS strong; scientific definitions distributed | strong locally, inconsistent across lineages |
| Literature | Program E and selected positioning notes | uneven; often later than model construction |
| Formalization | Mathematical Core and framework note | emerging and appropriately bounded |
| Experiments | very extensive across Research and Applications | strong quantity; protocol quality heterogeneous |
| Results | outputs, findings, JSON/CSV and report files | abundant; source-to-result links uneven |
| Review | evidence audits, replay reviews, meta reviews | mature in recent work; sparse in historical lines |
| Lab Report | clear in Rödelheim, finite validations and Translation pilots | missing as common endpoint |
| Archive | multiple archive trees and preserved history | strong preservation; successor links inconsistent |

## Where the flow already works

### Rödelheim 0.3

```text
bounded question
→ frozen protocol and withheld truth
→ experiment
→ negative result
→ freeze record
→ STOP_AND_RETAIN
```

### Prime and wheel/product validation

```text
predeclared claim
→ SPEC
→ deterministic execution
→ RESULTS
→ negative or bounded disposition
```

### Orientation Translation pilots

```text
fixed source
→ observation record
→ representation sequence
→ evidence boundary
→ pilot report
→ meta review
```

### IEEE Geometry V1

```text
manifest
→ development/evaluation boundary
→ generated artifacts
→ equivalence review
→ failed clean replay preserved
→ pause
```

## Primary divergences

1. Questions often appear after long exploratory runs rather than before them.
2. One program can contain many questions without one question registry.
3. Definitions migrate between visual, mathematical, semantic and application
   meanings without stable namespace labels.
4. Long experiment logs mix protocol, observation, interpretation and result.
5. Findings documents sometimes compress several experiments beyond their
   local evidence scope.
6. Literature comparison is systematic only in recent Programs B and E.
7. Archive placement does not always point to the current successor.
8. A completed experiment does not consistently terminate in one reviewable
   Lab Report.

## Missing navigation

The missing links are:

```text
question ID
↔ definition version
↔ protocol/experiment
↔ result
↔ review
↔ final Lab disposition
```

The Evidence Atlas solves claim-to-evidence navigation for selected claims.
The Repository Map solves directory navigation. The Control Desk solves
mission state. None currently owns this question-to-Lab relation. A read-only
Research-owned cross-reference is therefore the smallest unresolved need.
