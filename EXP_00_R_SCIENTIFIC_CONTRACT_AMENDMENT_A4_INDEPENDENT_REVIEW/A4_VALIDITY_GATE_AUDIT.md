# A4 Validity-Gate Audit

## Correct dependency semantics

A4 correctly distinguishes:

- N5-SYNTH failure → `IMPLEMENTATION_FAILURE`, registered access unreachable;
- mandatory post-authorization gate failure → `INVALID EXPERIMENT`;
- failed P1–P5 → failed scientific proposition, not invalidity;
- valid state without sufficient positive core → `NOT REPLICATED`.

The classification function places aggregate validity first, so a supplied false gate cannot become a positive label.

## Encoding blocker

The machine supplies a 26-token gate list, not a full executable validity graph. Examples:

- `INFORMATION_PARITY` lacks the exact equality fields for seeds, raw table, variables, actions, sampling, horizon, target/objective, and future/analytic access;
- `REPRESENTATION_DISTINCTNESS` lacks the prohibited same-fit/shared-score/calls-other predicates;
- `TRAIN_TEST_ISOLATION`, `PROVENANCE_COMPLETE`, and `CONFIG_BINDING_COMPLETE` lack required artifact fields and Boolean formulas;
- `ALL_12_SENSITIVITIES_COMPLETE` lacks the required per-variant coefficient/gain/support/provenance output schema stated in prose;
- the source/config integrity gate is not actually recomputed by A4's validator.

Thus a future runner could pass a named Boolean generated by different local criteria. Positive classification is unreachable after a *reported* false gate, but A4 does not force two teams to derive the same gate truth value.

These rules are already present in frozen V1 prose/code and A4 prose, so the missing machine predicates are class-B encoding defects rather than new scientific questions. **Validity-gate verdict: FAIL.**
