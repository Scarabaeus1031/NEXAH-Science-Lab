## Precise comparison

NEXAH has already built the **static root family, representation chain, return grammar and Coxeter periodicity**. The external game adds a particularly economical **local generator rule** that produces the family graph dynamically.

The user's `ABBA` memory belongs to the existing involutive return layer: if `A^2=B^2=id`, then `ABBA=id`. The user's Zither / `n-1` mechanism is a genuine structural analogue of reversal, but `J_n(k)=n-1-k` is an index reflection, whereas the game's `-x_i` is coefficient negation followed by neighbour addition. The neighbour sum is the missing operational piece.

## Boundary for the prime handle idea

The repository does contain the four Root7 channels `sqrt(2), sqrt(3), sqrt(5), sqrt(7)` and a 16-state sign family. That does not yet choose an ADE adjacency. A prime-labelled D4 star (for example center `3`, leaves `2,5,7`) would be a legitimate explicit model and should yield the D4-sized orbit 24. A literal `2-3-5` triangle with a `7` handle contains a cycle and is instead the natural non-ADE control; it should not be silently identified with E8.

## Decision

Do not start by inventing a new NEXAH module. First bind the mutation rule to the recovered modules above. The genuinely new test, if authorized next, is only the missing dynamic layer: local mutation plus family-graph generation, checked against the already validated E8 `240 = 8 x 30` benchmark.
