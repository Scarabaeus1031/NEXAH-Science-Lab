# Translation Layer Audit

## Strongest surviving formulation

NEXAH is best treated as an architecture for documenting and evaluating transformations among equations, simulations, trajectories, fields, critical summaries, partitions, graphs, visualizations, measurements, and decisions.

For each `T_ij: R_i → R_j`, a defensible record names the source and target types, operator/version, preserved relations, destroyed distinctions, reversibility, uncertainty, task relevance, and provenance. Translation Fidelity and T01 demonstrate that such records can expose collision, non-identifiability, decoder dependence, and false confidence from coarse stability.

## Classification

- The underlying mathematics is standard workflow/provenance, inverse problems, information theory, abstraction, and representation learning.
- The exact NEXAH bundle—registered transformations, certificate ladder, separate recovery/structure/dynamics fields, matched counterfactuals, collision counts, non-scalarized robustness/discrimination, and fail-closed loss statuses—is `ARCHITECTURAL_SYNTHESIS` and possibly distinct as engineering practice.
- Its incremental scientific utility over established provenance, model cards, data lineage, bisimulation, and information-theoretic evaluation is unvalidated.

The translation layer is consequently the strongest conceptual center, but only when operational. Naming two artifacts as views of the same system does not create a translation. A valid edge requires an explicit reproducible operator and correspondence record.
