# Architectural Contribution

The surviving contribution is architectural, but incomplete. It connects representations and records boundaries more coherently than any claim of a unified scientific kernel would permit.

| Arrow | Status | Evidence boundary |
|---|---|---|
| system→simulation | `PARTIALLY_IMPLEMENTED` | multiple dynamical codes exist; no single canonical system contract spans them |
| simulation→field | `CONCEPTUAL/PARTIAL` | the audited legacy field is independently generated, not traced from system state |
| field→structure | `IMPLEMENTED_UNVALIDATED` | derivatives and heuristic candidates execute; scientific semantics are narrower than labels |
| structure→partition | `IMPLEMENTED_UNVALIDATED` | nearest-maximum geometry, not demonstrated attraction dynamics |
| partition→graph | `IMPLEMENTED_UNVALIDATED` | region contact graph with severe information loss |
| graph→spectral/dynamics | `NOT_IMPLEMENTED_IN_CHAIN` | genuine separate graph lineage cannot be joined post hoc |
| representation→translation audit | `VALIDATED_AS_BOUNDED_WORKFLOW` | frozen studies record preservation, collision, and recovery statuses |
| translation→uncertainty | `PARTIALLY_IMPLEMENTED` | errors and losses recorded in selected studies; no universal propagation contract |
| uncertainty→decision/navigation | `CONCEPTUAL/UNVALIDATED` | T02 contract absent; ORION task owner absent |

The architecture is useful where arrows name an operator, code/data provenance, assumptions, information loss, and validation status. It becomes misleading when proximity in a diagram substitutes for an implemented correspondence. The contribution is therefore a disciplined integration and evidence-boundary architecture, not proof that the entire chain exists.
