# Documentation and Knowledge-Graph Baselines

The strongest baseline is a disciplined repository with code documentation, Git history, manifests, hashes, workflow lineage, FAIR metadata, and explicit negative-result notes.

Current incremental value is primarily a standardized combined view:

- mandatory `task_relevance: UNDEFINED` prevents silent application claims;
- object-specific preservation/loss slots expose Case B's compression;
- negative-result records can colocate Case D execution and rejected interpretation;
- directed edges expose the missing legacy graph→spectrum link;
- controlled statuses and evidence types support cross-project queries.

These are useful constraints, but ordinary structured metadata or a provenance/knowledge graph can implement them. The ledger is best understood as a constrained provenance multigraph focused on translation edges, loss/preservation assertions, task boundaries, and falsification history. That restriction is useful engineering, not scientific novelty.

At present, absent conforming instances, stable semantics, and a validator, value beyond competent documentation is `PARTIAL`.
