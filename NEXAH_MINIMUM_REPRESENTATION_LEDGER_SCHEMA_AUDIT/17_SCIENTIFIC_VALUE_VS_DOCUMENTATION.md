# Scientific Value versus Documentation

## Concrete value beyond prose

| Capability | Example in this audit |
|---|---|
| Machine-check missing links | basin graph has no verified spectrum continuation |
| Expose side inputs | partition consumes maxima plus grid/field context |
| Trace loss | partition→graph drops raster geometry, weights, directions, and field values |
| Prevent semantic inflation | nearest-seed partition is not an attraction basin; adjacency is not observed transition |
| Preserve negative evidence | decoder-independent hierarchy remains `NOT_REPLICATED` without deleting the edge |
| Fail closed on tasks | legacy and T01 entries validly state `task_relevance: UNDEFINED` |
| Block symbolic contamination | symbolic content cannot satisfy technical verification |
| Compare paths | multiple edges can connect types while retaining operator/version/provenance |

Ordinary documentation can say all of this, but cannot reliably enforce required fields, controlled states, referential integrity, or task/evidence conditions across many records. The machine-checkable constraints are the surviving incremental value.

At a high level the ledger is a NEXAH-specific synthesis of established data provenance, workflow lineage, scientific metadata, model-card/datasheet practices, knowledge graphs, reproducible pipelines, and FAIR principles. It is not a new scientific concept. Removed of the NEXAH name, it remains useful as a typed, falsification-aware transformation manifest.

If records are not bound to artifacts/evidence or no validator is eventually used, it collapses to useful documentation only.
