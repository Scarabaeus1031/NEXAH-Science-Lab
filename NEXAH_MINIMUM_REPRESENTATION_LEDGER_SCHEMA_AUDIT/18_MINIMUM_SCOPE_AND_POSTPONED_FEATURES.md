# Minimum Scope and Postponed Features

## Version 1 boundary

The minimum schema supports individual edges, typed endpoints/artifacts, four operator kinds, object-specific preservation/loss/introduction claims, simple uncertainty states, invertibility, optional task relevance, evidence/provenance, negative results, and ordered composition references. It is sufficient for the three legacy edges, the T01 classifier, and the Translation Fidelity failure record.

## Explicitly postponed

- universal ontology or automated semantic alignment;
- automatic loss, uncertainty, or task-utility propagation;
- theorem proving or equivalence checking;
- experiment orchestration or execution;
- databases, APIs, UI, dashboards, or visualization engines;
- cross-repository federation and identity resolution;
- AI-generated interpretation;
- automatic scientific status upgrades;
- canonical migration or retrospective artifact rewriting;
- task optimization, benchmark construction, and causal inference.

## Stop/reduction conditions

Stop or reduce to documentation if populated edges require invented semantics; provenance cannot be resolved; preservation/loss remains mostly untestable prose; deterministic checks catch no consequential errors; ordinary existing workflow metadata captures the same constraints at lower cost; records drift from code/data; or status owners routinely bypass negative results. Also stop expansion if the minimal examples cannot be independently reconstructed without NEXAH terminology.
