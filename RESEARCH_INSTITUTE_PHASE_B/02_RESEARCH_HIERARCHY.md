# Research Hierarchy

## Finding

The repository supports a nested identity model and a separate lifecycle. It
does not support one vertical hierarchy from Observation to Website.

## Scientific identity hierarchy

```text
Research Area
└── Research Program
    └── Research Question
        └── Lab or bounded Study
            ├── Scientific Object
            ├── Method or Protocol
            ├── Experiment or Derivation
            ├── Result and Evidence
            └── Report and Disposition
```

Only Question, Lab/Study, Object, Method, Result, Evidence and Report are
consistently observable as scientific objects. Program and Area identity is
less complete and often implicit.

## Lifecycle overlay

Every object in the hierarchy may occupy a local state and a lifecycle phase.
These dimensions must remain separate:

```text
identity: Question / Lab / Program / Area
phase:    QUESTION / RESEARCH / EVIDENCE / REVIEW / ...
status:   ACTIVE / FROZEN / STOP_AND_RETAIN / ...
maturity: FOUNDATION / WORKING / SPECULATIVE / ...
evidence: supported / partial / unvalidated / unsupported / ...
```

No value on one axis determines another. 【CON; ARCH; CD】

## Public and repository continuation

After Review, a result may branch:

```text
Review
├── STOP / retain negative evidence
├── revise Question or Method
├── remain Research reference
├── seek Adoption into Framework, OLS or Application
├── become a Library publication through Library authority
└── be presented by Experience / Website after publication authority
```

The Library and Website are therefore destinations or views, not higher
scientific ranks.
