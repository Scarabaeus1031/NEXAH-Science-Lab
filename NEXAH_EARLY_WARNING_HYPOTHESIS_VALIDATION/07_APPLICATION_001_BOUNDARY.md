# Application 001 Boundary

## Logical separation

```text
APPLICATION 001
  = reproducibility / IEEE geometry replay / orientation usefulness

EARLY-WARNING EXPERIMENT
  = new scientific hypothesis validation
```

Application 001 uses the existing frozen IEEE Geometry V1 benchmark path to
help a specialist audit replay and evidence boundaries. Its product/scientific
status remains `PROPOSED / NOT_ADOPTED`. It explicitly prohibits stability,
early-warning, risk, prediction, causal, control and operational claims.

The early-warning experiment asks whether a new candidate statistic has held-
out anticipatory value. It needs a separate Science Lab manifest, code,
validation record and Owner authorization. A future Level-2 transient adapter
would be an experimental source boundary, not an expansion of Application 001.

## Non-interference rules

- do not change Application 001's contract, runner, operators, scorecard or
  claim language;
- do not treat Application 001's IEEE-9/14 geometry gate as early-warning
  evidence;
- do not import early-warning results into its Orientation Brief;
- do not call a Level-1 synthetic PASS an Application 001 capability;
- do not weaken `ordered_load_scale_not_time`, `not_observed`, or any current
  prohibited claim;
- no ORION, NEXAHEDRON, Experience, LUCY, LYRA or Interface V1 dependency.

## Decision conclusion

Application 001 does not need to change. No architecture decision is required
to preregister an isolated Science Lab experiment. Owner authorization is
required before implementation/execution and any later repository adoption.
