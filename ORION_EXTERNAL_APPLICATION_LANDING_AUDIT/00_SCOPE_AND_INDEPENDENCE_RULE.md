# Scope and Independence Rule

This is a design/research-only audit asking whether an independently existing
application can supply the reduced ORION MVP's task, tolerance, latency,
reliability and failure consequences. It does not build, implement, simulate,
preregister or run anything and cannot create an owner's approval.

The measurement platform remains a nonmagnetic rigid body, identified asymmetric
fiducial, IMU, global-shutter camera and independent encoded reference.
`NEXAH_METHOD = UNDEFINED`.

## Independence test

Every candidate requirement is classified as:

- `EXTERNALLY_ESTABLISHED`: a standard, binding project requirement or qualified
  owner already fixes it independently;
- `EXTERNALLY_MOTIVATED_BUT_NOT_FIXED`: the domain defines the quantity but a
  project/owner must provide its value;
- `INTERNALLY_CHOSEN`: selected for this platform;
- `UNKNOWN`: provenance not established.

Only the first closes a contract field. The causal test is whether the task and
failure problem would exist if ORION and NEXAH disappeared. Compatibility with
the existing bench is evidence of fit, never evidence of independence.

Source statements are labeled `SOURCE_FACT`; conclusions drawn for this audit are
`AUDIT_INFERENCE`. Standards and official requirements take precedence, followed
by primary literature/datasets, official instrument documents and reviews.
