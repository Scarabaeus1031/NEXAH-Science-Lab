# Research Roadmap

## Operating rule

No new operator names during this roadmap. Work may define records, measurements, hypotheses, or domain specializations. Promotion occurs only after the admission test in the backbone proposal.

## Phase 0 — Freeze and index

Goal: stop vocabulary drift before further experiments.

- Freeze the ten OLS names and IDs.
- Publish the Library/OLS/scientific-operator vocabulary boundary.
- Freeze the corrected Gate interpretation.
- Freeze the three JANUS identities.
- Mark the Atlas chain and historical operator families as non-canonical.
- Create one current operator index and one historical crosswalk.

Exit condition: a reader can determine the owner, status, definition, and canonical source of any current operator label without searching historical directories.

## Phase 1 — Define common records

Goal: make existing experiments comparable without inventing new spaces.

- Draft typed Transition v0.1.
- Draft Path v0.1.
- Draft BoundaryRecord taxonomy v0.1.
- Draft RepresentationMap v0.1.
- Draft OrientationQuery/Focus v0.1.
- Encode one graph, IEEE, cluster, and continuation example.

Exit condition: each example preserves its domain semantics, insufficiency, provenance, uncertainty, and non-composable fields.

## Phase 2 — Validate retained numerical measures

Goal: determine whether Gate and DCO add information beyond simpler baselines.

- Pre-register Gate and DCO hypotheses.
- Freeze formulas and estimator parameters on development data.
- Establish null and ablation baselines.
- Use held-out systems and repeated seeds.
- Report false positives, false negatives, calibration limits, sensitivity, and failure cases.
- Demote either measure if it does not outperform a simpler explanation.

Exit condition: one reproducible validation report per measure, including negative results.

## Phase 3 — Independent operator-contract reproduction

Goal: test whether OLS-guided orientation can be reconstructed outside the current editorial lineage.

- Recruit independent analysts.
- Freeze source material and task before construction.
- Compare contract completeness, type agreement, boundary preservation, and unsupported conclusions.
- Record template effects and author dependence.

Exit condition: agreement and disagreement are quantified; no authority change is inferred from recurrence.

## Phase 4 — Reader outcomes

Goal: test artifact-level orientation claims.

- Run biology reader-boundary test.
- Run chemistry composition/function test.
- Run repository-navigation test using current versus reduced indexes.
- Measure correctness, boundary recognition, uncertainty retention, path selection, time, and subjective preference separately.

Exit condition: results show where the reduced architecture helps, does nothing, or creates new error.

## Phase 5 — Cross-domain portability

Goal: test contract portability without mechanism collapse.

- Apply the same record contracts to one biological, one chemical, one power-system, and one abstract dynamical case.
- Keep domain equations, units, mechanisms, and validity criteria separate.
- Test only shared record behavior and semantic boundaries.

Exit condition: common fields and irreducibly domain-specific fields are both documented.

## Phase 6 — Admission review

Goal: decide, not expand.

For each candidate:

- retain;
- merge;
- rename;
- freeze;
- demote;
- or mark obsolete.

Default decision: no promotion.

## Stop conditions

Stop a line of work when:

- its behavior reduces completely to an existing operator;
- the candidate cannot be distinguished from a simpler baseline;
- required data do not support its contract;
- repeated tests show unstable meaning across representations;
- its main evidence remains shared vocabulary or visual resemblance;
- the cost of maintaining a new name exceeds its demonstrated explanatory value.

Stopping is a successful reduction result.
