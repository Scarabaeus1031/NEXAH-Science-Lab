# Tube and Port Typing

The frozen architecture already expresses:

```text
typed input state
-> declared interface boundary
-> channel and/or transformation under a regime
-> declared interface boundary
-> typed output/result
```

A port is therefore an interface role at which a typed state, signal or record enters or leaves a bounded process. It is not a new primitive; RID/SWM source, operation, event, result and interface records can carry the necessary identity, provenance, loss and validation constraints.

`PORT_STATUS=EXISTING_INTERFACE_CONCEPT_SUFFICIENT`

“There is always a change in the tube” is too strong: identity transformations and lossless passages are possible, while some changes may be outside the declared observable. As a metaphor for a bounded channel/regime it is compatible, but not a law.

`TUBE_STATUS=ANALOGICALLY_COMPATIBLE`

`PORTAL_WORDPLAY_FORMAL_AUTHORITY=NO`. PORT, PORTAL and PORT-AL supply no etymological or scientific derivation.
