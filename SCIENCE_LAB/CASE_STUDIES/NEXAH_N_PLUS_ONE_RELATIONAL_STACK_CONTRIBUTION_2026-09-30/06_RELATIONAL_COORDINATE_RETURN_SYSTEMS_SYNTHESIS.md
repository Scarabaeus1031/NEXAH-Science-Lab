## The 111 boundary pair

The exact arithmetic identity is:

```text
111^2 = 12321
110*112 = (111-1)(111+1) = 12320
111^2 - 110*112 = 1.
```

Its repository use has an additional zero-based address distinction:

```text
111 x 111 capacity: 12321 records; addresses 0..12320
112 x 110 capacity: 12320 records; addresses 0..12319
```

Therefore `12321` may name a capacity while `12320` may name either the final
address of the first grid or the capacity of the second. Every implementation
must store the type with the integer. The existing half-turn
`R(x)=12320-x` belongs to the finite `111 x 111` address carrier; the arithmetic
identity alone does not transfer that operator to every `12320/12321` view.

This pair is the smallest clear demonstration of the candidate's purpose: a
one-unit numerical relation can correspond to different grid capacities,
coordinate systems and address domains, so relation metadata cannot be
replaced by the displayed number alone.

## Digit-permutation carrier family

The existing bounded audit records, among others:

```text
11357 = 41*277
11537 = 83*139
```

The two integers share the multiset `{1,1,3,5,7}` but have different numeric
values, factorisations, CRT fingerprints and grid addresses. Other
rearrangements such as `11375` may be used only after they enter a declared
carrier register with their own factorisation and residues.

Consequently:

```text
same digits != same number != same address != same generator.
```

The established repository label `FIBONACCI_ADJACENT_DIGIT_LENS` is
documentary. It becomes a testable operator only after an edit, permutation or
substitution rule is fixed. “Prime-digit wheel” may be used as a human-facing
visual label only when it is made clear that the complete integers need not be
prime.

## CRT, QRT and relational slices

The existing CRT slice audit already supplies the bounded state:

```text
(CRT class c, shell quotient q, slice parameter t).
```

For `M` equal to the declared CRT modulus product, an integer representative
can be written as:

```text
x = c + q*M.
```

An intermediate display coordinate may be introduced as a representation
fiber, for example `x(t)=c+t*M`, without creating a new CRT residue class.
The slice coordinate or another injective multichannel record is required to
recover an interior state.

This supports a precise relational extension question:

> Does storing the CRT address together with slice, provenance, mapping path,
> information ledger and return residual improve defect detection or
> localization over an ordinary master-frame or residue representation?

The candidate representation can be written schematically as:

```text
E = (local records, residue/address channels, relations,
     quotient/slice context, provenance, I-L-A-U, return residuals).
```

This is an architecture candidate, not a new Chinese remainder theorem. A
technical implementation must distinguish:

```text
k information channels
+ r deliberately redundant check channels
+ 1 Binder/decoder contract.
```

The `+1` is not simultaneously a quotient, observer, parity symbol and Binder.
Each role requires its own field and test.

## Mobile reference views and the exterior channel

The existing slice audit binds three different view types:

```text
pi       -> rotation view
phi      -> scale view
sqrt(2)  -> Cartesian diagonal view
```

These views can distinguish collisions that another projection hides. They do
not generate new CRT states and do not become a coordinate system merely by
being displayed together.

The root-grid audit separately binds independent radical sign choices for
`sqrt(2), sqrt(3), sqrt(5)` and an added `sqrt(7)` coordinate, yielding Q3 and
Q4 hypercube state graphs. In that contract, `sqrt(7)` is an additional
algebraic sign coordinate. Calling it an “outside observer” is permitted only
as a visual explanation unless a separate observation map defines what it
receives and returns.

Likewise, `sqrt(i)` may serve as a complex phase or orientation view only after
the selected branch and transformation are explicit. It is not silently added
as another ordinary spatial axis.

## Hinge, Scarab and path equality

The Portalstone record establishes the exact commutative relation:

```text
2101 + 2901 = 2*2501 = 5002
2*5002 = 10004.
```

The historical Scarab plate uses the same integer `2501` as a `Bridge Node`.
The shared integer and midpoint relation are exact; the Scarab transition
operator remains unestablished. The safe common grammar is:

```text
different declared paths -> one compared endpoint.
```

This is also the bounded meaning of “the hinge is the relation.” The Hinge is
the typed equality or comparison between paths, not a new substance, physical
gate or automatic proof that the paths preserve the same information.

## Builder bridge: UDF, NXA, SCARAB, XVA and `.scrb`

The provenance-bound historical source contains working JSON-driven browser
players and structured UDF, NXA and SCARAB examples, plus planning language
for XVA, SCARAB and control-plane formats. The intake found no standalone
`.xva`, `.scrb`, `.nxa` or `.scarab` container implementation, frozen common
schema, converter or efficiency benchmark.

The durable connection is therefore architectural:

```text
historical player/container prototypes
  -> declarative local records and rendering rules
  -> stable identities, states, queries and signatures
  -> n+1 Binder relation record
  -> deterministic return and loss inspection.
```

`.xva` and `.scrb` remain possible future serialization profiles, not the
scientific contribution itself. The contribution candidate should first be
implemented with an existing carrier such as JSON plus glTF/GLB or USD. A new
extension or container becomes justified only if the matched benchmark shows
that established carriers cannot express the required contract cleanly or
efficiently.
