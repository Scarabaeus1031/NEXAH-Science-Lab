# 07 — Execution / Event Boundary

For `z_{n+1}=z_n²+c`, distinguish:

1. rule specification: `f_c(z)=z²+c`;
2. selected parameter: `c`;
3. selected initial/current state: `z_0` or `z_n`;
4. iteration event: an actual registered application at step `n→n+1`;
5. resulting state: `z_{n+1}` or an error/failed outcome;
6. orbit/trace: the ordered accumulation of states or records.

The equation specifies the mathematical recurrence. It does not attest that software executed it. A numerical MJPR run has separate provenance, configuration, iteration occurrences, outputs, and traces.

```text
RULE != EXECUTION
PARAMETER != EXECUTION
RULE_DEFINITION != ITERATION_EVENT
ITERATION_EVENT != RESULTING_STATE
ORBIT != RULE
ORBIT != PARAMETER
TRACE != GENERATING_EVENT
```

An orbit is a mathematical ordered sequence generated by the recurrence from specified data. A stored finite orbit can also serve as a trace representation, but it is not the execution event itself and need not preserve the full event provenance.

`ITERATION_RULE_EQUALS_ITERATION_EVENT=NO`  
`RULE_EQUALS_EXECUTION=NO`  
`ORBIT_EQUALS_RULE=NO`  
`TRACE_EQUALS_EVENT=NO`
