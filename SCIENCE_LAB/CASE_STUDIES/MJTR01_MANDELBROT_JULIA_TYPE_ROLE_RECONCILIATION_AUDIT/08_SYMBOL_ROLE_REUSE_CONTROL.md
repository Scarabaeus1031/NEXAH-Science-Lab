# 08 — Symbol / Role Reuse Control

The phrase “two c's” is imprecise unless it refers to two written occurrences. In a fixed expression/context, the occurrences can denote the same bound complex value while doing different syntactic work:

- `c∈C`: member/selected parameter;
- `f_c`: index selecting a member of the parameterized family;
- `z²+c`: constant term used by the selected rule;
- `J_c` and `E_c`: indices selecting the object or finite representation associated with that value;
- `c'∈Θ_y`: a candidate variable in an inverse/compatibility construction, not automatically the true selected `c`.

Therefore:

`SAME_SYMBOL_IMPLIES_SAME_VALUE=CONTEXT_DEPENDENT`  
`SAME_SYMBOL_IMPLIES_SAME_ROLE=NO`  
`SAME_PARAMETER_VALUE_CAN_OCCUR_IN_DISTINCT_FORMAL_CONTEXTS=YES`

No duplicate parameter is created by repeated notation. Conversely, the same glyph in a different scope can denote a different variable/value; symbol identity alone does not determine binding or role.
