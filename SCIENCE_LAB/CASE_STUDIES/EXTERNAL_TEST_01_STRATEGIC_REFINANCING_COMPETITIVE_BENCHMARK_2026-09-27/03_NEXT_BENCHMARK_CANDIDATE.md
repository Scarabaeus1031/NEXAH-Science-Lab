## Purpose

Convert the exploratory finding into a valid Decision-Assurance test without
redesigning the wider ecosystem.

## Minimum frozen design

1. Create one synthetic or fully licensed case with a ground-truth timeline,
   repayment schedules, tax and liquidity rules, and three to five seeded
   consequential errors or ambiguities.
2. Freeze the identical input packet, platform/version capture procedure,
   allowed tools and output deadline before any result is viewed.
3. Score correctness, critical-defect detection, evidence discipline,
   hidden-assumption detection, boundary identification, reproducibility,
   calibrated abstention, recommendation quality and review time.
4. Compare NEXAH with a strong equal-information professional baseline and at
   least one relevant multi-model or answer-comparison service.
5. Have at least one qualified external evaluator score blinded outputs against
   the frozen answer key.

## Minimum demonstrable NEXAH workflow

```text
NORMALIZED SOURCE REGISTER
  -> COMMON TIME AXIS AND MODEL
  -> OUTPUT CLAIM EXTRACTION
  -> FACT / CALCULATION / ASSUMPTION / RECOMMENDATION TYPING
  -> REPRODUCIBLE COUNTER-CALCULATION
  -> DIFFERENCE-TO-ASSUMPTION TRACE
  -> BOUNDARY / SENSITIVITY / ABSTENTION
  -> HUMAN RETURN WITH AUDIT TRAIL
```

## Pre-customer build gate

Before a real customer test, the workflow needs one frozen input schema, one
calculation-and-assumption ledger, one reproducible comparison output and one
read-only review surface. A broad platform, automated recommendation engine or
new theory is not required.

## Stop rule

If NEXAH does not improve at least one preregistered primary outcome against the
strong baseline without materially worsening review time or false confidence,
the specific advisory-report wedge is not supported by that test.
