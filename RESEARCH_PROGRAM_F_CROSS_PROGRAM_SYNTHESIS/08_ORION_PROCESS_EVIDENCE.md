## Documents not required for the primary-chain decision

The following remained useful as corpus boundaries but supplied no unique decision input:

- Program B visual-intuition and not-mathematics inventories;
- Program C strongest modular/CRT ranking and most non-Rödelheim claim rows;
- Program D application records unrelated to AP-05, AP-08, and AP-09;
- Program E graph, transition-system, barycenter, and trajectory benchmark details;
- repeated README and final-recommendation count tables after their owning inventories were read.

They remain historical and audit evidence. Program F does not mark them obsolete.

## Duplicated fields

- status and maturity;
- evidence location and evidence status;
- dependencies and missing prerequisites;
- validation and external-review requirements;
- risks, stop rules, and non-claims;
- next permitted action;
- repeated totals and final return records.

Duplication made conflicts visible but required repeated scope reconciliation.

## Rules that prevented overclaiming

- one question counted once;
- supported means supported only within exact recorded scope;
- failed and negative evidence remains unchanged;
- scientific language follows established fields;
- repository terminology moves to provenance;
- no maturity transfer across evidence, implementation, application, and literature-overlap layers;
- one primary chain only;
- no implementation, experiment, contact, or publication under documentation authority;
- explicit STOP and result classes.

## Rules that caused unnecessary work

- full repeated maturity and dependency fields in A–E;
- separate final recommendations that restate inventories;
- application-wide and claim-wide reads when the selected chain used only a small subset;
- repeated terminology and non-claim tables;
- multiple priority systems without a named axis such as evidence repair, application readiness, or next scientific result.

This is process evidence, not authorization to redesign ORION.

## Unresolved authority gaps

- no named canonical Research/Validation owner for the Lab 0.4 protocol package;
- no authority record selects the canonical source snapshot and hash owner;
- no protocol-review gate owner;
- no external-review nomination and release authority beyond Thomas's general authority;
- no single rule states which maturity layer controls when Programs disagree in vocabulary.

## Compression finding

A–E can be compressed into a reusable future workflow:

```text
question inventory
→ evidence binding
→ practical-object boundary
→ established scientific language and methods
→ cross-program consistency audit
→ one chain selection
```

Program A is an optional feasibility branch when a selected question has no executable source object. It is not required for every question.

## Finding for ORION 1.0 RC review

The process successfully prevented unsupported promotion and exposed dependency errors. Its main cost is repeated scope-ambiguous status data. A later RC review should evaluate a single scope-qualified trace record rather than five repeated inventories. Program F makes no runtime or governance change.
