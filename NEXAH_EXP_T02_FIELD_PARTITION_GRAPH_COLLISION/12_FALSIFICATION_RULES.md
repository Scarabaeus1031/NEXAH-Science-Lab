# Falsification Rules

- `F1_BASELINES_SUFFICIENT`: all registered loss events are identified/localized
  with equal or better clarity by B0–B7. Consequence: incremental value not supported.
- `F2_THRESHOLD_DEPENDENCE`: any primary collision conclusion reverses at either
  frozen threshold control. Consequence: method weakened; no robust claim.
- `F3_CORRESPONDENCE_RESOLVES_COLLISION`: a collision disappears when canonical
  source IDs are applied. Consequence: original collision invalid.
- `F4_ORDER_DEPENDENCE`: reversed seed/node insertion changes canonical P/G.
  Consequence: fail affected result.
- `F5_CONSTRUCTION_FAILURE`: B fails `P!=P' and G=G'`, C fails required candidate
  count or `G!=G'`, or any candidate-seed bijection fails. Consequence:
  `PRECONDITION_FAILED`; no substitute.
- `F6_LEDGER_REDUNDANT`: ledger changes no registered conclusion beyond B0–B7.
  Consequence: incremental value not supported.
- `F7_ONLY_KNOWN_MANY_TO_ONE_RESTATEMENT`: collisions are fully and more simply
  described by standard partition/graph comparisons. Consequence: no distinct
  diagnostic contribution.

Additional fail-closed conditions: protocol hash mismatch, missing manifest,
unexpected result files at start, nonfinite value, malformed ID, incomplete
correspondence, or primary expectation relabeled post hoc.

Negative and null outcomes remain reportable. None authorizes retuning.
