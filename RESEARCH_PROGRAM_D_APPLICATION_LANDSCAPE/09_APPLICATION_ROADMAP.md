# Application Roadmap

This roadmap routes existing work. It does not authorize implementation, validation, publication, or outreach.

## Stage 0 — Preserve boundaries

- keep the fourteen application IDs stable within Program D;
- keep `NOT AN APPLICATION` exclusions visible;
- retain Program C statuses and all failed/negative evidence;
- do not recast historical narratives as current capability.

Exit: each application points to owning evidence and an explicit non-claim.

## Stage 1 — Demonstrate only bounded objects

- AP-01: existing IEEE showcase;
- AP-02: illustrative network fixtures;
- AP-03: reference Lorenz visualization;
- AP-04: offline frozen comparison;
- AP-05: method-boundary review package;
- AP-14: deterministic core behavior only.

Exit: demonstrations contain no stronger claims than their evidence.

## Stage 2 — Repair existing evidence breaks

1. AP-11 directional-statistic freeze and baseline/null review;
2. AP-01 bounded external reproducibility review with G4 unchanged;
3. AP-06 claim/evidence and reader-navigation evaluation.

Exit: existing ambiguity is reduced before new application work begins.

## Stage 3 — Validate one human-facing method

Run only the already recommended AP-07 reader test under separate authority. Do not add another translation pilot first.

Exit: bounded reader outcome, including null or adverse result.

## Stage 4 — Complete mathematics before implementation

1. AP-09 representation-map and loss definitions;
2. AP-10 relation-derived observable definitions.

Exit: each object has domains, outputs, equivalence, baselines, and failure conditions.

## Stage 5 — Admit one new research instrument

AP-08 may proceed only after Stage 4 does not impose unresolved dependency changes and a separate protocol-design authorization exists.

Exit: one frozen synthetic result and stop.

## Parked

- AP-12 until an interoperability owner and two-implementation path exist;
- AP-13 until observed evidence and domain/safety partners exist.

## Stop rules

Stop when:

- a practical problem cannot be stated without project terminology;
- evidence supports only a visual, scenario, or narrative;
- a blocked application is presented as validation-ready;
- implementation is proposed before required mathematics;
- operational or causal language exceeds Program C status;
- the work would create a new operator, framework, book, or product.
