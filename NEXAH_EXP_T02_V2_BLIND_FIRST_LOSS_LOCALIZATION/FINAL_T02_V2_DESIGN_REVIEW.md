# Final T02-v2 Design Review — Freeze Refused

## Exact estimand status

The first-loss estimand is mechanically exact. For public task distinction
`Delta`, paired representations and correspondence, the exact survival vector is
well-defined, monotone by fixture contract, supports `NO_LOSS`, and yields a
unique `k*` (`01_SCIENTIFIC_ESTIMAND.md`). Generator labels can be procedurally
blinded from diagnostic modules.

## Fatal issue

The same facts that make truth identifiable also make the proposed incremental-
value comparison trivial. N4 receives:

1. the target observable named by the public task query;
2. its source-to-stage aliases from public correspondence;
3. exact left/right values at every stage.

N4 predicts `k*` by exact target inequality followed by the first `1->0`
(`diagnostics_nexah.py`). A conventional direct plug-in baseline given the same
fair inputs performs the identical calculation. It requires no collision ledger,
NEXAH concept or hidden truth.

The draft B0–B6 pool omits that decisive fair baseline. Consequently:

- without B7, a positive N4 result measures asymmetric access to task semantics;
- with B7, N4 is a deterministic re-expression and cannot exceed the strongest
  comparator or create baseline-output collision witnesses.

Thus Q1 is a valid instrumentation benchmark, but Q2 cannot distinguish
incremental diagnostic value from definitionally evaluating the estimand. This
is the exact failure mode the task requires the self-review to catch.

## Plain answers

1. **Estimated:** the first monotone stage at which an exact declared observable
   distinction becomes equal, or `NO_LOSS`.
2. **Truth independently defined:** yes, by the generator oracle, separate from
   diagnostic outputs.
3. **Can NEXAH know via construction/correspondence:** yes—not from a leaked label,
   but because public query+correspondence+values directly suffice to compute it.
4. **Baselines genuinely independent:** the implemented draft modules are, but
   the comparator registry is incomplete without the fair exact task baseline.
5. **Can threshold discrepancy create H1:** no; primary comparisons are exact.
6. **Can constructed control support H1:** no by the draft rules.
7. **Can `NO_LOSS` win:** yes and it is explicitly represented.
8. **Can baselines completely defeat NEXAH:** yes; the fair B7 is definitionally
   identical to N4.
9. **Every decision executable:** no, because the required fair comparator and
   resulting nontrivial H1 do not exist in this design.
10. **Scientifically worth executing:** no. Q1 is predetermined instrumentation;
    Q2 is unfair without B7 and impossible with B7.
