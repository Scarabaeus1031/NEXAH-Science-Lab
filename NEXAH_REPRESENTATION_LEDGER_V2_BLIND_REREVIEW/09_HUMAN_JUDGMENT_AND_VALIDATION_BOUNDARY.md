# Human Judgment and Validation Boundary

V2 explicitly marks `DETERMINISTIC`, `RULE_GUIDED`, `EXPERT_JUDGMENT`, and `UNKNOWN` for boundaries, assumptions, criteria, provenance sufficiency, status dimensions, and claim support. Machine-readable no longer implies machine-decided.

The documentation unmistakably says schema validity is not scientific truth. Nevertheless misleading schema-valid records remain possible:

| Attempt | Syntactic outcome | Scientific outcome |
|---|---|---|
| valid source pointer attached to unrelated claim | accepted | requires referential/scientific review |
| criterion unrelated to claimed object/edge | accepted | demonstrated by C scope mismatch |
| contradictory top-level and detail status values | accepted | schema defect |
| duplicate/conflicting claim IDs | accepted | uniqueness/reference check absent |
| fabricated bounded number with plausible method/evidence text | accepted | requires evidence inspection |
| execution rhetoric used as confirmation | representable, but separate claim support reduces risk | scientific review required |
| symbolic evidence correctly labeled nontechnical | cannot support claim IDs | caught |
| symbolic item falsely relabeled technical | accepted | evidence-eligibility review required |

Validation theater is reduced and explicitly bounded, not eliminated. A validator specification can own referential checks after the three schema blockers are repaired.
