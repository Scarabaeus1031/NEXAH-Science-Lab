## The five things to remember

### 1. Return is not identity

Several different views may reconstruct one source without becoming the same
carrier or the same operator. This is established by BL-024, BL-045, BL-047,
BL-049 and BL-055.

### 2. Return is not compression

A record may return every source and still cost the same number of bits as the
raw source ID. BL-055 establishes this directly: Q106 and Decimal D4 return
exactly but do not save bits. Only the Typed Seam saves under the frozen
contract.

### 3. Missing information must remain visible

Lossy views require a residual, an additional view or retained history.
BL-021, BL-022, BL-024, BL-025, BL-035 and BL-049 show distinct versions of
this rule.

### 4. Exact mathematics does not choose a historical mechanism

Valid arithmetic, symmetry or Return can coexist with noncanonical pairing,
underdetermined placement or missing source semantics. BL-045, BL-046, BL-047,
BL-048, the Euler comparator and BL-054 make this boundary explicit.

### 5. Negative results are design knowledge

The failed prime score, Root-Room decoder, Euler-specific spectrum and
all-view Ghostgrid stability are not lost work. They tell the Bench which
controls, warnings and abstentions must be visible.

## Practical consequence for the Bench

The Bench should not merely animate shapes. Each demonstrator should expose:

```text
SOURCE → VIEW → LOST INFORMATION → RESIDUAL / SECOND VIEW → RETURN
                         ↓
                  COST + CONTROL + ABSTAIN
```

The first integrated implementation is present in OCB `v0.17.0`: the
Return Economy demonstrator uses BL-024, BL-025 and BL-049, with BL-055
controlling the comparison meter. It shows that all three return exactly while
only one currently saves bits. The six visible phases are
`SOURCE → VIEW → RESIDUAL → RETURN → CONTROL → COMPARE`.

The new Coupled Window System applies the same discipline to the whole Bench:
ten task windows group existing modules without merging their carriers. Its
first dedicated application, the BL-036 Moving Aperture Window, makes a simple
lesson visible: equal local sums can hide different placements, so the
measurement alone is not enough; address, operator, boundary and residual are
needed for a safe Return. This is an engineering application of accepted
method, not a nineteenth experiment or a promoted scientific finding.

The Aperture Invariance Observatory now turns that lesson into 56 finite
engineering comparisons under identity, cross-carrier comparison, rotation,
reflection, translation and a control permutation. The Coupled Session Ledger
preserves selected window states as comparable receipts. These are reusable
inspection tools; they do not change the portfolio count or activate a study.

## Scientific consequence

The portable result is a typed audit method for representation and Return.
The nonportable part is the claimed advantage: economy, canonicality,
mechanism and physical meaning must be tested separately on each carrier.

No new experiment or demonstrator build is activated by this synthesis.
