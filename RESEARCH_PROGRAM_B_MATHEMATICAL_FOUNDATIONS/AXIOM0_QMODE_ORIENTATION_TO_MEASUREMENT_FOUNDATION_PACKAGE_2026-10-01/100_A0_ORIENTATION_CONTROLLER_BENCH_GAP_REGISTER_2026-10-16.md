## 1. Purpose

This record preserves the remaining gaps of the **A0 Orientation Controller
Bench (OCB)** after the `v0.11.0` implementation pass. It is a documentary
attachment to the canonical
[A0 Research Backlog and Open Joints](24_A0_RESEARCH_BACKLOG_AND_OPEN_JOINTS_2026-10-10.md),
not a second backlog, a new Study, a Run Contract or authorization to continue
development during Structure Freeze.

The register distinguishes four states:

| State | Meaning |
|---|---|
| `BUILT` | present in OCB `v0.11.0` and covered by the local deterministic test suite |
| `PARTIAL` | a bounded mechanism or view exists, but the intended instrument or its evidence/interaction contract is incomplete |
| `SOURCE_ONLY` | supplied visual or historical HTML informs the design, but no OCB implementation or exact source reconstruction is yet bound |
| `OPEN` | no accepted implementation or formal contract exists |

## 2. Protected baseline — do not rebuild

The following work is already present and should be treated as the baseline:

  `CARRIER → P_VIEW → BINDER → A_VIEW → RESIDUAL → RETURN`;

The next pass should close the gaps below instead of adding another unrelated

## 3. Priority 0 — make aperture measurement inspectable

### OCB-GAP-01 — one trace, three measures, four projections

Status: `PARTIAL`

The present iris-to-octagon projection is visually working, but it is not yet
an explicit three-coordinate measurement instrument. Add one declared trace

```text
M3(t) = (h(t), A(t), I(t))
```

with:

1. `h(t)` — height/elevation coordinate;
2. `A(t)` — azimuth/orientation coordinate;
3. `I(t)` — aperture/opening coordinate.

The same samples must be inspectable in four representation modes:

```text
UNROLLED TRACE → ROLLED/CYLINDRICAL TRACE → TOP VIEW → APERTURE SLICE
```

Acceptance boundary:

- sample count, ordering and values remain unchanged across all four views;
- every view declares its coordinate map and units or explicitly states
  `NORMALIZED / UNIT NOT ESTABLISHED`;
- switching view changes representation only, not the carrier record;
- the exported record contains the three measures, active view, cut and
  residual;
- a deterministic test proves representation invariance and records any
  information hidden by the selected cut.

Source cue: owner-supplied visual `CEEA9960-8FC7-4FAE-A532-35088CF210EF_1_105_c.jpeg`
(`Eine Spur · Vier Projektionen`). The image is a design reference, not an
executable specification.

### OCB-GAP-02 — aperture-stack calibration

Status: `SOURCE_ONLY`

The proposed stacked apertures should become a controlled calibration view,
not a decorative tower. The supplied sequence `51.63° … 52.13°` in `0.10°`
steps may be entered only as a declared source-local fixture.

Required contract:

- one fixed axis;
- ordered aperture plates;
- plate index, nominal angle and signed `Δθ`;
- the same `M3(t)` trace viewed through each plate;
- an explicit comparison of what each plate retains, hides or introduces;
- a reference plate and return condition;
- no prime-number, physical, astronomical or causal interpretation.

Completion requires a source fixture, calibrated range, units, tolerance and a
non-special control stack with the same number of plates.

Source cue: `5594C644-4C9A-46EF-8DC6-298020D1A5B6_1_105_c.jpeg`
(`The Muindi Aperture Tower`).

### OCB-GAP-03 — observing cut and difference record

Status: `PARTIAL`

OCB already separates source, view, residual and Return in several modules.
What is missing is one compact comparison instrument:

```text
SOURCE S(t)
  → APERTURE / CUT
  → VIEW A + VIEW B
  → Δ(A,B)
  → RETAINED / LOST / INTRODUCED / UNRESOLVED
  → BOUNDED RETURN OR STOP
```

Acceptance boundary:

- `A` and `B` are separately parameterized views of a declared source;
- `Δ(A,B)` states its metric or remains `UNDEFINED`;
- the I/L/A/U ledger is exported with the state record;
- equal-looking views do not imply equal carriers;
- Return does not erase the recorded gap.

Source cue: `399FCBC1-C50D-4721-B004-7D3B938B6B22_1_105_c.jpeg`
(`The Observing Cut`).

## 4. Priority 1 — connect aperture, binder and bounded return

### OCB-GAP-04 — A·i·l typed aperture control

Status: `SOURCE_ONLY`

Preserve the supplied distinction:

```text
A = global selection
i = local point
l = local turn
S(t) → A·i·l → visible form
```

Before implementation, define the domain and codomain of each operator and
show which part of the state each operator changes. Global/local axes and glyph
families may be compared but not identified. The output remains a visible
form, not a linguistic, mathematical or scientific identity claim.

Source cue: `D0CFDD73-9412-4C2C-ABC1-C908904DC1C2_1_105_c.jpeg`.

### OCB-GAP-06 — three systems plus one binder

Status: `PARTIAL`

ERITH and the historical Three-LIFE source already supply neighboring design
grammar. OCB still lacks one explicit multi-system ledger that keeps these
channels separate:

```text
SIGNAL → TRACE → RETURN
```

for `SYSTEM A`, `SYSTEM B` and `SYSTEM C`, with one separately typed binder.
The proposed HH sequence may be used only after its steps are declared:

```text
HH seed → H+ / H− split → 3 systems + 1 binder → 9 views → bounded return
```

Acceptance boundary:

- each system retains its own carrier and state address;
- the binder stores typed handoffs rather than merging the systems;
- signal, trace and Return are separately exportable;
- `HH′ ≠ HH` remains an admissible result;
- no biological or physical mechanism follows from the LIFE label.

Source cues:

- `C0840A2B-1646-45FB-86E7-C9EA4158659E_1_105_c.jpeg`;
- `62527A7F-F802-40C7-B716-C9BBDEA4A217_1_105_c.jpeg`.

### OCB-GAP-07 — one guided OCB story

→ M3 MEASUREMENT
