A record conforms to Toolbox v0.1 only when it:

1. names exactly one admitted signature version;
2. supplies that signature's required inputs and provenance;
3. preserves source, frame, operation and output as separate roles;
4. emits typed `I / L / A / U`, residual and return state;
5. retains the local evidence basis and claim ceiling;
6. abstains or fails when required information is missing;
7. does not promote visual similarity, endpoint equality or successful replay
   into identity, causality, truth or Human usefulness.

# Minimum Shared Orientation Record v0.1

**Side path from the [Master Reading Path](../00_OVERVIEW/README.md):** the

**Status:** `FROZEN_DOCUMENTARY_ENVELOPE / NOT_OLS_EXTENSION / NOT_RUNTIME_SCHEMA`

**As of:** `2026-10-03`

## Purpose

The minimum shared Orientation Record is the smallest documentary envelope
that can carry a conforming Aperture/Boundary, Projection or Relation result
without merging their distinct semantics. It preserves how a record arose,
what the admitted signature could and could not establish, and what must be
returned to a Human.

It is not a replacement for OLS, CRIC, NRRC, CARC, an experiment's native
schema or a domain record. Implementations may map an existing contract into
this envelope only when the mapping and any loss are declared.

## Required common fields

| Block | Minimum content | Rule |
|---|---|---|
| `identity` | `record_id`, record version, creation authority | the record has its own stable identity |
| `source` | source identities, provenance pointers, evidence status | a representation or relation never replaces its source |
| `context` | purpose, domain, scope and admitted interpretation | context bounds meaning and comparison |
| `frame` | observer or viewpoint where relevant, boundary/aperture, inclusion/exclusion and scale | omitted frame information is recorded as `U`, not guessed |
| `operation` | signature ID/version, parameters, maps or binding rule and preregistered criteria | operation and output remain separate |
| `output` | typed result reference plus signature-local payload | one envelope may carry different output types without flattening them |
| `audit` | typed retained `I`, lost `L`, added `A` and unresolved `U` items | empty classes are explicit; unknown is not zero |
| `residual` | residual type, comparison criterion, value or structured difference, tolerance and status | residual is local to the declared comparison |
| `return` | exact local state, normalized category, claim ceiling and Human action options | replay or zero residual does not force closure |
| `evidence` | authoritative pointers, receipt/replay hashes and test status | evidence provenance travels with the result |

Normalized return categories are limited to `PASS`, `FAIL`, `HOLD` and
`INVALID`. The exact signature-local return code must also be retained; the
normalization does not erase distinctions such as
`PASS_BOUNDED_WITH_DECLARED_LOSS` or `INVALID_INPUT`.

## Keep three limits separate

1. **Analytic blow-up / loss of regularity:** property of a precisely specified PDE solution.
2. **Physical model boundary:** the continuum description no longer adequately represents the physical system.
3. **Numerical failure:** discretization, resolution, conditioning or algorithmic failure prevents reliable computation.

They may be evidentially related, but none is identical to another. Simulation failure is not proof of blow-up; mathematical singularity is not a molecular account of a real fluid.
